- **Raw results:** `sweep-{vi,en}-{320,375}.json`, `sweep-vi-820.json`, `sweep-en-1280.json`, `targeted.json`, `literals-shown.json`.

## Method and limits

**How the app was served.** `dist/` was served through `page.route` at origin `https://kitchen.test`, with service workers blocked and the app in device-only mode (`bep-local-locked`). Every `/.netlify/` call got a local stub reply, and every other host got a 404, so no live API was called. The browser tried to reach only one outside host: `fonts.googleapis.com`.

**Test data.** Each page was seeded through the app globals:
- onboarding marked done;
- a week generated by `familyGenerate` from the library;
- a third family member;
- three pantry lots (fridge, freezer, dry);
- one extra shopping item.

**What the sweep did.**
- Opened all 8 screens: Hôm nay, Thực đơn, Đi chợ, Món ăn, Tủ, Chi tiêu, Gợi ý, Sản phẩm. It also opened the account menu and the offline state.
- At each screen, tapped every control that has a data-action-style attribute (91 taps per run). Then it tapped every action inside each sheet that opened (two levels deep). This opened 27 sheets per run.
- Opened 7 more sheets directly through globals: `stockForm` (edit and add), `otherSettingsModal`, `storesModal`, `pushSettings`, `recipeForm` and `showRecipe`.
- Ran in VI and EN at 375×812 and 320×740. Screens only (no tapping) at 820×1100 (VI) and 1280×800 (EN).
- Used Chromium viewport simulation with reduced motion on, timezone Australia/Sydney, light theme.

**Not covered:**
- Physical devices. Viewport simulation is not a test on real hardware.
- Account mode and family sync. These need the live API, so the account-menu items behind sign-in were not opened.
- Studio. It needs an owner sign-in, so Studio was checked from source only.
- The ladybug feedback panel and the self-test (autoplay) panel. Both are only shown to invited or owner accounts.
- Sheets more than two taps deep.
- Taps the crawl skips on purpose: destructive actions and anything that would leave the app.

**Severity scale.**
- **High:** the family sees a broken rule on a common path, or the privacy page is wrong.
- **Medium:** a clear rule breach on a less common path.
- **Low:** minor or cosmetic.

Only verified findings are listed. Each one was seen in the browser, or shown by exact code with its output (marked "code").

## Rules 19–21: phone emoji

The in-page interface is clean. `emoji-art.ts` replaces each emoji with a drawing, or removes it, in text, `<option>`, `title`, `aria-label`, `placeholder` and `document.title`. The sweeps found **no phone emoji** visible on the 8 screens or the 34 sheets, in VI or EN, at any size.

The remaining emoji are in text that leaves the page, where `emoji-art` cannot reach.

### D1 · Medium · Đi chợ → "Chia sẻ danh sách" / copy list: shared text is full of phone emoji

- **Exact output:**
  ```
  🧺 ĐI CHỢ NHÀ MÌNH · 9/11–15/11
  🥩 Thịt, cá & hải sản
  □ Thịt heo: 1.18 kg
  🥬 Rau củ & nấm …
  🧂 Trứng, gia vị & đồ khô …
  🛍️ Đồ khác …
  ```
  Each store line starts with `🏪`.
- **Code:** `src/frontend/app.ts:90` (`textShopping`). The group emoji come from `src/frontend/seed.ts:4` (`GROUPS`). The function is called at `app.ts:171-172` (`share-shopping`, `copy-shopping`).
- **Evidence:** `targeted.json` → `share.textShopping`, captured from the running app.
- **Fix:** build the text with plain words for headings and items. Keep `✓`/`□` only if Henry approves them as text marks. Change the copy and share paths together (rule 29).

### D2 · Medium · Errand request ("Nhờ mua thêm"): push notification and share text carry 🛒 📍 📝

- **Code:** `src/frontend/push-ui.ts:33` (`requestText`).
  - The text is sent as the Vietnamese push `body` at `push-ui.ts:34`, so it appears as a system notification on the recipients' phones.
  - The same text is shared by `share-request` at `push-ui.ts:36`.
  - `requestTextEnglish` (`push-ui.ts:39`) has no emoji.
- **Evidence:** code.
- **Fix:** drop the emoji, or use words: "Mua thêm: …", "Ở: …", "Ghi chú: …".

### D3 · Info · Dead code still holds emoji share text

- `app.ts:91` (`textWeek`: 🍲 ☀ ☾) and `app.ts:173` (`share-day`: 🍲 ☀ ☾) hold emoji share text.
- At runtime these are replaced by the family-menu versions. The `textWeek()` output in the app had no emoji.
- **Fix:** remove the dead code so it cannot come back.

### D25 · High · The feedback privacy page says only the operator reads feedback, but reports are filed as public GitHub issues

- **What the page says:** `dist/feedback-privacy.html:63/77`: "Chỉ người vận hành ứng dụng đọc góp ý" / "Only the app operator reads feedback".
- **What the server does:** `src/netlify/functions/feedback.mts:45` calls `fileIssue` for every new report. `src/netlify/lib/feedback-github.mts:2-6,22-23` posts the reporter's words, recent device errors and technical context as an issue in the **public** repo `nguyentuanphu/10GD` whenever `FEEDBACK_GITHUB_TOKEN` is set. Studio says so openly: "công khai" (`studio-feedback.ts:62`).
- **Also affected:** automatic self-test reports (described on the same page) go the same way.
- **Fix (needs Henry first, rule 28):** either say on the page that the words and technical details are published publicly on the app team's issue list, or file to a private repository.

### D26 · Medium · Third-party requests from the device are not on the privacy page

- **Who receives the device's IP address:** Google Fonts on every page load; jsDelivr when receipt reading or voice is used; Hugging Face when a voice model is downloaded; supermarket image CDNs whenever product photos show.
- **Why the page is misleading:** it says receipts and on-device voice stay on the device. That is true for the content, but the libraries and models are fetched from third parties.
- **Fix (needs Henry):** add a "Thư viện và hình ảnh tải từ bên ngoài" section, or self-host the fonts, libraries and models.

### D27 · Medium · Weather lookup is not on the privacy page

- **What happens:** the city typed in "Thời tiết" is sent to the app server (`personal-ui.ts:192,206`), which gets the forecast from Open-Meteo (`src/netlify/lib/weather.mts`). The result is kept in the family settings.
- **Privacy page:** has no entry for this.

### D28 · Medium · "Tìm giá online" search words are not on the privacy page

- **What happens:** the word typed is sent (`price-scout-ui.ts:201`) and stored in a shared list (`src/netlify/lib/online-wanted.mts`). It is passed to Pinch / WhichGrocer, its prices are shown to every family that searched the same word, and it is visible in Studio.
- **Privacy page:** has no entry for this.

### D29 · Low · Voice statistics send more than the page says

- **What is sent:** a SHA-256-derived household code (`voice-stats.ts:43`) and a per-device token header (`voice-stats.ts:63`), with the words. The household code is the same every time, so reports from one household can be linked together.
- **What the page says:** §3 mentions only "chữ đã xác nhận".

### D30 · Low / Info · App-update events are sent from every device, including device-only, and are not described

- **Code:** `app-update.ts:123-125`, posting to `studio?op=client-event` by beacon.
- **Content:** technical only (event type, reason, outcome, build).
