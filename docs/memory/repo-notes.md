# Repo notes (build and test facts)

- **Build:** `npm run build` compiles `src/frontend/*.ts` to `dist/*.js` and `src/tests/*.cts|mts` to `tests/`. The browser test scripts do NOT rebuild, so build first.
- **Browser tests:** they serve `dist/` through Playwright `page.route` on `https://kitchen.test`, with service workers blocked. Device-only mode is set through localStorage (`bep-local-locked`, `guest/bep-language`, `bep-theme-mode`). See `src/tests/unit-picker-browser.test.cts`. App globals (`state`, `currentWeek()`, `save()`, `render()`, `closeModal()`) seed data.
- **Screenshots:** test runs overwrite screenshots under `docs/reviews/**`. Restore with `git checkout -- docs/` and `git clean -fd docs/reviews` (exclude the current release folder) before committing.
- **Known local-only failure:** `test:v1713:browser` (narrow VI order) fails in the cloud sandbox and passes on GitHub CI; it fails on `main` too.
- **Fixed race, 12 Nov 2026:** `test:voice-default:browser` used to fail locally and once on CI ("0/0 MB"). The small fake files kept reporting progress after the chip appeared. The test now waits for the progress to settle before setting its numbers. Lesson: an "environmental" failure is a race until proven otherwise; find it.
- **Fixed race, 13 Nov 2026 (Viết món “Tỏi3”, lost amounts):** the sheet keep-in-place in `app.ts` (`SHEET_KEEP`, includes `[data-rci="add"]`) re-checked the tapped button at 250 and 600 ms. Typing the new row's name opens the suggestion list, which pushes the add button down, so the late check scrolled the sheet ~22 px; when that landed between the touch on a suggestion and its click, the click hit `.rc-sug` instead of the option, the pick was lost and the amount went into the name. It failed only in part (e) of `recipe-ingredients` and only in whole-file runs under load (3 of 40), never with CPU throttling (that slows both sides). Found with a capture-phase event log (pointerdown on the option, click on `.rc-sug`); console logging hid it. The hold now ends on the next pointerdown/touchstart/wheel/keydown/input, like the page hold; part (g) of the test fails on fc50523 every time. Lesson: a timer that moves the screen after a tap must stop when the person acts again.
- **Cancelled CI:** a CI run on a superseded commit is cancelled. It reports "npm run test:all failure" with 0 failed jobs; that is not a real failure. Check the jobs with `gh api repos/nguyentuanphu/10GD/actions/runs/<id>/jobs`.
- **CI layout:** CI splits every `test:all` step into parallel jobs, read from `package.json`, so a new suite is picked up automatically once it is in `test:all`.
- **Weeks:** weeks are keyed by the family's start day, `planStartOf(state,date)`. Never use Monday.
- **Push links:** a push notification link must match the same pattern in three places: `src/netlify/lib/push.mts` (server; unknown links fall back to `/#shopping`), `src/frontend/sw.ts` (falls back to `/#today`) and `src/frontend/household-ui.ts` `pushOpenHash`.
- **Bootstrap:** `src/frontend/bootstrap.ts` holds the ordered script list. A new frontend module must be added there.
- **Skill copies:** the henry-master skill seen in sessions is a synced copy of Henry's claude.ai skill. Local edits to it do not persist; Henry updates it on claude.ai.
- **Listeners after the app's own handler:** the app's `change` / `click` handlers usually call `render()`, which replaces `#main`. A later listener for the same event sees a detached target, so `target.matches('#main …')` is false. Read `dataset` values first and match without `#main` (found with the extra-surplus question, v1.7.19).
- **Shared unit picker:** `openUnitSheet` (`unit-picker.ts`) opens the unit picker as a second sheet inside `#modal-root`, over the form that asked. For rows in a list, add a hidden input + button with `unitFieldMarkup({id,cls})` and register the id prefix with `registerUnitRowField`. Tests pick a unit with the button `.unit-field-btn`, then the chip `#unit-sheet-layer .unit-chip[data-unit-choice=…]`, then `[data-unit-sheet-act="save"]`.
- **Sandbox: `kitchen.localhost` does not resolve** (13 Nov 2026). `test:authenticated-startup` fails locally with `getaddrinfo ENOTFOUND kitchen.localhost`, on old heads that passed CI too. Fix on the machine only: `echo "127.0.0.1 kitchen.localhost" >> /etc/hosts`; then it passes.
- **Sandbox: Playwright version.** After `npm ci` the repo's pinned Playwright looks for a browser build the machine does not have. Locally only, link `node_modules/playwright` and `node_modules/playwright-core` to `/opt/node-tools/node_modules/…` (never commit; CI installs its own). Do not run `playwright install`.
- **Merging minified one-line files.** W-agent branches conflict on whole lines of `app.ts` etc. Split each version at `;` `{` `}` into lines, `git merge-file` the three versions, then join back; only true overlaps remain.
- **Tự chạy thử (autoplay), 12 Nov 2026:** scenarios register through `bepAutoplay.register` with `workflow:true` (Workflow trọn vẹn), `audit:true` (Rà soát 12/11, `ladybug-audit.ts`) or neither (Kiểm tra nhanh). Every scenario ends with the shared rule-33 step (`roundTrip` in `ladybug-autoplay.ts`: `validImport` + four sync merges). The screens' filters (Món ăn search/tab, pantry chip, shopping range) are reset per scenario and put back afterwards. `test:autoplay-audit:browser` proves each audit check fails on a deliberately broken app; add a breaker there for each new check.
